## 起動

Node.js 22以上で `npm install` → `npm run dev`。表示されたローカルURLを開きます。
`npm test` で週集計・日付処理、`npm run build` で公開用ファイルを作成します。

- 複数プロフィール、目標優先順位、運動の週目標、食事目標、運動メニュー編集

初期の運動メニュー・目標は編集可能な仮設定であり、過去会話で確定した個人用処方ではありません。

## Firebaseを接続する

1. FirebaseプロジェクトでAuthenticationのメール／パスワードを有効化。
2. Firestoreを作成し `firestore.rules` をルールとして反映。
3. `.env.example` を `.env.local` にコピーし、Webアプリの設定4項目を入力。
4. `npm run dev` を再起動。設定画面から新規登録／ログイン。
5. 公開ドメインをAuthenticationの承認済みドメインに追加。

Storage、Cloud Functions、AIサービスは使用しません。接続先はユーザー本人のUID配下です。同じアカウント内のプロフィール切替を実装しています。家族別アカウント間の共有は未実装です。
端末モードの既存データはログイン先へ自動移行しません。JSONを先に書き出してください。Firebase実接続は2026-10-22に検証済みです。検証結果は `firebase-verification.json` を参照してください。

Firebaseキャッシュの方式は公式仕様に準拠: https://firebase.google.com/docs/firestore/manage-data/enable-offline

## 公開・PWA

`dist/` をHTTPSの静的ホスティングに配置。相対パスのためサブディレクトリ公開にも対応します。
サービスワーカーは本番ビルドでのみ有効です。インストール時に画面の静的資産をまとめてキャッシュします。
iOSではSafariの「共有 → ホーム画面に追加」で利用します。192/512pxのPWAアイコンと180pxのApple用アイコンを同梱しています。
端末内のデータはブラウザデータ削除で失われるため、JSON書き出しを利用してください。

## 第2段階（2026-10-22）

- 8種目のマスターに、やり方・感じやすい部位・フォームミス・注意点と6部位タグを追加。既存の種目はIDまたは一致する名前で参照し、自由入力の種目も継続利用できます。
- 負荷は1メニュー100ptを基本に、完了100%、一部50%、未実施0%。未記録は0ptのまま未記録として表示し、回数の実入力は求めません。複数部位は均等配分します。これはアプリ内の記録指標で、医学的な運動負荷ではありません。
- 記録日の属する月曜から記録日までをプロフィール別に集計し、部位別スコアの少ない種目を上位3件に提案。同点は短時間を優先し、当日の実施済み種目・表示中のメニューは除外します。疲れ気味・休みたいと保存した日は自動の追加提案を控えます。週の数値目標や個別処方は設定していません。
- 「＋もう少しやる」で1分・2分・5分以内の種目から選択。追加分は当日のexerciseLogsにplanned:falseで保存し、追加直後は未記録です。基本メニューには入りません。
- 当日の未記録メニューは「今日のメニューを変更」から差し替え可能。実施記録のある種目は履歴を保つため差し替えを拒否します。基本メニューの変更は従来どおり設定画面から行えます。
- 当日変更・基本メニュー変更ともに「外的制約／自分都合」を必須とし、変更前後・記録日・変更日時を保存します。
- 公的な参考情報は厚生労働省「身体活動・運動ガイド2023」への小さな折りたたみ表示。根拠辞書と種目のevidenceIdsを分離し、将来は根拠のある提案にだけ出典を紐づけられます。現在の部位順位・配点・各メニュー量をガイドラインの推奨とは表示しません。

## 第3段階：週レビュー（2026-10-24）

「週の進捗」内に、実績 → 本人の感覚 → 来週の希望 → 来週の事情 → ツール提案 → 本人承認の6段階を追加しました。日次画面で選択中の過去日とは独立して、端末の今日を基準に直前の確定済み月〜日をレビューします。月〜水を推奨期間とし、木〜日もレビューできます。承認曜日にかかわらず次の月曜から適用し、現在週の途中には切り替えません。例えば10月19日（月）〜25日（日）の承認は10月26日から、10月26日の承認は11月2日からです。

- 先週の運動達成日、食事・任意目標（完了1／一部0.5）、活動区分、体のために何かした日、特別活動、筋トレ負荷・部位別負荷、変更理由をプロフィール別に集計します。有酸素種目と部位不明の自由種目は筋トレ集計から除き、全運動負荷には含めます。
- 日次入力に任意目標達成、通常／軽運動／セルフケア、体のために何かした、特別活動を追加しました。日次保存時に提示メニュー・目標・週回数も保存します。旧記録にない活動区分や提示回数は推測しません。回避傾向の提示回数は記録または変更で確認できた回数であることを表示します。
- 筋力刺激・活動量・習慣継続・食事目標はアプリ独自の◎／○／△。対象の記録がない場合は「—」。実際の活動時間・生理的な刺激を測定する評価ではありません。
- 変更が同一対象で2回以上あると、外的制約なら時間・場所に合う種目への見直し、自分都合なら短時間・少量からの継続を候補にします。理由を断定しません。
- 運動・食事・任意目標の負担感、増減希望、来週事情をルールベースの提案へ反映します。提案の各項目を採用／編集／変更しないから選び、確認チェック後に承認します。種目の差し替え・内容・記録負荷の編集も可能です。医学的処方を生成する機能ではありません。
- 提案にevidenceIdsを保持します。現在の週提案はすべてアプリ独自ルールなので公的根拠ラベルは表示しません。

### 保存と互換性

`users/{uid}/profiles/{profileId}/weeklyReviews/{profileId}_{weekStart}` にsummary／input／proposal／decisionsと、`weeklyPlan: {effectiveFrom, values}` を保存します。既存ルールの予約済みweeklyReviewsを使うため、Firestoreルール・認証・既存コレクションの変更はありません。ローカルの旧保存形式には空のweeklyReviewsを補い、既存記録を保持します。JSON書き出しにも含まれます。

開始日以前の画面には反映せず、開始日以降で最新の承認済み計画を適用します。計画は次の承認計画まで継続します。同じ対象週の再承認はその週レビューを更新し、元の基準から再提案するため減量が重複しません。基本設定の目標より承認済み週計画を優先することを設定画面に表示しています。過去の承認内容は次の週に上書きされません。レビュー中の入力はプロフィール・アカウント別のメモリに保持し、承認前のページ再読み込みでは破棄されます。

## 選択式入力・活動の自動判定（2026-11-02）

- 設定の優先順位は候補を上下に並べ替え。食事・任意目標は候補選択、運動メニューはマスターのチェック選択。週レビューの編集も選択式。名前・記録メモは引き続き入力可能です。
- 旧カスタム項目は表示して保持。設定保存でも既存種目のID・内容・負荷・順番を維持し、未知の旧種目は削除しません。食事目標変更前の値は変更履歴に残します。
- 完了または一部完了の運動記録から通常→軽運動→セルフケアの優先順で日ごとに自動分類。実施なしは未記録。旧手動activityTypeは週集計では参照せず、記録そのものは保存したままです。通常は筋トレ種目、ウォーキング・足踏み・ストレッチは軽運動、首肩のセルフケアはセルフケアです。
- 特別活動は別ボタンから複数追加。10候補＋5時間帯、対象活動だけ任意の整数歩数。dailyLogs.specialActivitiesにtype／duration／steps／ruleVersionを追加し、旧specialActivity文字列も保持します。「その他」と旧文章は活動量評価の対象外です。
- 特別活動の活動量は時間帯ごと10／25／50／90／150ptと、歩数対応活動の100歩あたり1ptの大きい方（重複加算なし）。独自の記録指標です。週の活動日にも反映し、運動負荷・筋トレ負荷・部位スコアには一切加算しません。大掃除・重作業も筋トレの代わりにはしません。活動量の◎／○／△は従来同様に活動日数で評価します。
- Firebaseのコレクション・ルール・認証・保存キーは変更なし。運動記録には自動分類用のactivityKindを追加。移行・既存データの一括書き換えは不要です。
